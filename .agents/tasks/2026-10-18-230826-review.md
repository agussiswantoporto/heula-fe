# iOS visual polish: refreshed tokens, floating pill tab bar, screen sweep

The change retunes the design tokens in `globals.css` for a genuine iOS feel (larger card radius, a new control radius, true near-black dark grouped surfaces, softer diffuse shadows, a frosted-surface alpha), elevates the shared primitives to those tokens with subtle motion (Button press-scale, Segmented/Sheet spring tuning), rebuilds the `BottomTabBar` into a floating rounded iOS pill with a `layoutId` active highlight, and reserves the matching bottom space in `AppShell` and `ToastProvider` so nothing hides behind the pill. The rest is a presentation-only sweep across the Home timer, history, stats, profile, offline and onboarding screens so they all read from the refreshed token system in light and dark. No logic, data, copy, props, routing or icons were touched. Watch for: a dead `withTabBar` prop added to AppShell whose `false` branch no caller ever uses, and whose doc comment describes route-hiding behavior that does not happen (confirmed).

**Verdict**: APPROVED

## High-level view

The token refresh is the foundation: `globals.css` keeps the Tailwind v4 CSS-first structure (`@theme`, `:root`/`.dark`, `@custom-variant dark`, `@utility safe-*`) and the emerald brand tokens, while retuning radii, shadows and both palettes and adding `--radius-control`, `--frost`/`--frost-surface` and `--hairline` for downstream use. Everything else references these tokens rather than ad-hoc values.

The tab bar is now a floating, fully-rounded, translucent pill detached from the edges and centered in the phone-width column, with the old thin top-bar highlight replaced by a spring `layoutId` blob behind the active tab. Accessibility is handled: `aria-label` on the nav, `aria-current="page"` on the active link, `min-h-[44px]` hit targets, and a visible `focus-visible` ring.

The floating pill forced a layout follow-through: AppShell reserves pill height plus gap plus safe-area on tabbed routes, and ToastProvider's stack was raised to clear the same reserved band, so Home's Start/Stop controls and bottom-scrolled content stay visible.

The screen and feature sweep is purely cosmetic — large iOS titles with safe-area top spacing, a bigger monospace timer readout, grouped-list history headers, control-radius inset fields and choice rows — with all copy still read from `copy.ts` and all timer hydration/motion/gating logic intact.

The one soft spot is the new `withTabBar` prop on AppShell: it is wired to reserve-or-not bottom space, but no caller passes `false`, so the branch is dead and its doc comment claims a route-hiding behavior that the committed layout does not implement.

### Floating pill BottomTabBar

The bar is wrapped in a `pointer-events-none` fixed outer container (`inset-x-0 bottom-0`, `mx-auto max-w-[480px]`, `px-4`, `pb-[calc(0.75rem+env(safe-area-inset-bottom))]`) that positions a `pointer-events-auto` `<nav>` styled `rounded-pill bg-[var(--frost-surface)] border border-border shadow-card backdrop-blur-xl backdrop-saturate-150`.

```
 ┌─────────── fixed, pointer-events-none, max-w-480, safe-bottom pad ───────────┐
 │   ┌──────────────── nav: rounded-pill, frosted, hairline, shadow ────────┐   │
 │   │  [home]      [history]      [stats]      [profile]                    │   │
 │   │   └── motion layoutId "tab-highlight" bg-brand-soft springs behind ───│   │
 │   └───────────────────────────────────────────────────────────────────── ┘   │
 └──────────────────────────── home indicator below ────────────────────────────┘
```

The old thin top-bar highlight is replaced by an `absolute inset-0 rounded-pill bg-brand-soft` blob carrying `layoutId="tab-highlight"` (spring stiffness 500, damping 40), with the icon/label at `relative z-10`. Links use `min-h-[44px]` for the hit target, `aria-current="page"` when active, and `focus-visible:ring-2 focus-visible:ring-brand` for a visible focus style. Only the four existing IconKeys (`tab_home`/`tab_history`/`tab_stats`/`tab_profile`) are used.

### Layout follow-through and the dead withTabBar branch

AppShell changes the reserved band from `pb-[calc(64px+env(safe-area-inset-bottom))]` to `pb-[calc(56px+1.5rem+env(safe-area-inset-bottom))]` (pill height + bottom gap + safe-area), and ToastProvider raises its stack from `bottom-20` to `bottom-[calc(56px+1.5rem+1rem)]` so toasts clear the same band. Home's `mt-auto pb-4` Start/Stop controls therefore stay above the floating pill.

The gap is the new `withTabBar` prop. AppShell now accepts `withTabBar = true` and only applies the reservation when true, and its doc comment asserts that on onboarding/offline the bar is hidden and no space is reserved. But `layout.tsx` is unchanged from the base branch: it renders `<AppShell>{children}</AppShell>` with no prop and `<BottomTabBar />` unconditionally. There is no `Chrome.tsx` in this repo. So the pill actually renders on every route (pre-existing behavior from the base, out of scope as a regression), the `false` branch is unreachable, and the comment describes behavior the code does not implement. Harmless at runtime but worth tidying.
